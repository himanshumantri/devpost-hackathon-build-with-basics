CheckdIn — App map

A one-page guide to where things live, so you know where to start when you want to change something.

What it is, in three pieces

CheckdIn matches travelers at the same airport who board around the same time and share interests, then lets them chat. The people shown are fictional samples.

FrontendThe five screens you see: Welcome, Basic Information, Interests, Travellers near you, Chat. React, in frontend/src/.
BackendA small Python program that holds the data and applies the matching rules. FastAPI, in backend/app/.
Data filesThe airport list and the sample people, in backend/data/. No database.

One action, followed through the code

You press Continue on the Interests screen. This is what happens.

The route: three stops

This is the route to follow with the app open. Search for the name shown after each file.

Stop 1 · The request leaves — frontend/src/api.js

Search for getMatches. It packs your airport, boarding time, interests and venues into a request to /api/matches. It is the only file in the frontend that talks to the backend.

Stop 2 · The request arrives — backend/app/main.py

Search for post_matches. It receives the details and hands them to the rules. models.py next to it rejects a badly formed request before it gets here.

Stop 3 · The rule decides — backend/app/matching.py

Search for find_matches, then the line if gap > MAX_GAP_MINUTES:. That line is "within one hour", written in code. The interest and venue rules are the two functions above it, interests_match and venues_match.

To change this, start here

If you want to…Start in
Change a heading or wording on a screenfrontend/src/screens/ (for example the heading "Travellers near you" in NearbyPeople.jsx, a small edit already made)
Change colors, fonts or spacingfrontend/src/styles.css (colors are the variables at the top)
Change who matches whombackend/app/matching.py (the two rule functions, MAX_GAP_MINUTES and MAX_MATCHES)
Add or edit sample peoplebackend/data/sample_people.json (restart the backend after editing)
Add an interest or venue optionfrontend/src/options.js and backend/app/models.py. They must list the same choices.
Change how long chats are rememberedfrontend/src/chatStore.js (THREE_HOURS_MS)

A practice to reuse

Turn each requirement into something you can check. The product requirements said matches must board "within one hour" of each other. That became a precise statement: exactly 60 minutes apart is included, 61 is not. It now lives as the test test_exactly_sixty_minutes_apart_is_included_and_sixty_one_is_not in backend/tests/test_matching.py, and it passes.

On another project, write the observable result next to each requirement before asking an agent to build it, then ask for a test or a check that proves it. A requirement you can check is one you can trust.

See the test and run it 
cd backend
.venv\Scripts\activate
pytest

Expected: all tests pass. A pytest run takes about a second.

Run it again

Two terminals, each starting in the project's top folder:

# terminal 1
cd backend
.venv\Scripts\activate
uvicorn app.main:app --reload --port 8000

# terminal 2
cd frontend
npm run dev

Open the address the second terminal prints (http://localhost:5173). The full steps and a demo path are in README.md.
